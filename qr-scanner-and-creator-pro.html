Google Play Data Safety (Mandatory Disclosures)

In accordance with the Google Play Console Data Safety requirements, the developer certifies the following states:

  • ✔ No User Data Collected: The Application does not transmit, collect, or upload any personal or sensitive user information to remote servers.

  • ✔ Offline Execution: The application does not require internet permissions to execute its main scanning, parsing, or creation functions, making cloud leakage technically impossible.
  • ✔ Zero-Data Retention Policy: Since we store absolutely nothing in the cloud, there are no remote user databases. Users possess absolute autonomy to wipe their localized history journals in one tap.

2 Hardware Permissions & Local Use-Case Disclosures

To allow core functionalities to compile on-device, the Application requests isolated system-level access. Below are the functional details of these requests:

Camera Access (android.permission.CAMERA)

Technical Purpose: Used exclusively to instantiate the device's hardware camera and stream frames directly into our local parsing library for barcode recognition.

🔒 Security Boundary: Processing is fully dynamic and on-the-fly. No raw frames, photographs, video streams, or pixel parameters are ever encoded to local disk storage, nor are they exported to internet networks.

Scoped Document Operations (Storage Access Framework)

Technical Purpose: Enables exporting your scan records to Excel (.xls) or CSV spreadsheets, or importing lists of text lines to generate codes in bulk.

🔒 Security Boundary: The Application strictly implements Android's modern Scoped Storage specifications. It does not request general read or write privileges for your entire device filesystem. File actions are sandboxed within the System Document Picker.

Intent-Based Contact Insertion (vCard Integration)

Technical Purpose: Allows users to convert scanned contact card (vCard) fields directly into a local address book contact.

🔒 Security Boundary: The Application does NOT declare or request the highly invasive READ_CONTACTS or WRITE_CONTACTS permissions. Instead, it securely formats the scanned parameters and invokes Android's native Contacts System Interface via Intent. The OS processes the final addition, keeping your directory safe from independent app access.

3 The Zero-Collection and Zero-Tracking Policy

The Application does not collect, manage, store, or sell any information that falls under the classifications of Personal Data, Personally Identifiable Information (PII), or Sensitive Personal Information (SPI) under GDPR, KVKK, or CCPA regulations.

No Tracking SDKs: We have deliberately omitted advertising tracking scripts (e.g., Google AdMob, Facebook Audience Network), behavioral analytics modules (e.g., Firebase Analytics, Flurry), and user feedback SDKs. All code generation algorithms are computed offline on your processor.

4 Local Database Security & Data Retention Control

Your persistent scan records are archived within an isolated, local SQLite database container (History Journal) allocated to the app's secure internal sandbox.

  • These database records are physically inaccessible to other apps installed on the system.
  • Users retain 100% control over database logs. You can wipe all history entries permanently at any time using the clear utility in the Application's local settings.
  • Uninstallation Clean-up: In accordance with native Android OS policies, uninstalling QR Scanner & Creator Pro immediately, permanently, and irreversibly deletes the entire localized database sandbox and all configuration properties from your hardware.
